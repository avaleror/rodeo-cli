## Open items (unchanged priority, none critical)

### 1. `rancher.py` monolith — 2,053 LOC (medium)
Still the single largest module and the highest regression surface (K3s + Helm + Rancher
+ Gitea + Harvester import + Elemental all in one file). ROADMAP defers the split; no raw
`time.sleep` remains, so the correctness risk is contained — this is maintainability only.
**Suggested:** split `elemental`/Edge concerns out first (smallest, most separable slice).

### 2. Ownership tagging — ROADMAP B1 (medium)
`clean`/`stop`/`start` still discover VMs via substring/glob hints rather than a
`rodeo:plan=<name>` marker in domain XML. Prerequisite for `rodeo destroy` and for the
Phase E cloud targets. Not yet started.

### 3. Reconcile-by-default — ROADMAP B2 step 5 (medium)
`--reconcile` is opt-in and covers VM memory/vCPU drift only. Remaining: a live
memory-resize→redeploy cycle on bare-metal KVM, then flip the default and add
`--no-reconcile`. Topology/pxe/cluster drift stays manual (V2).

### 4. `time.sleep()` in CLI command loops (low)
`start_cmd`, `stop_cmd`, `restart`, `clean`, `start_if_needed_cmd` still use raw
`time.sleep()` in their wait loops. `app.py` is acceptable (TUI refresh). The CLAUDE.md
rule targets *engine poll loops* (clean) — these are one-shot CLI waits, lower risk, but
worth a `self._sleep`-style cancellable helper if these commands ever grow stop events.

### 5. `--output json` for `plan`/`status` (low)
Still absent (ROADMAP Phase D). Needed for CI-driven checks of drift/status.
