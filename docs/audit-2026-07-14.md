## Critical / high severity

### 1. Phase-level idempotency hides resource drift (known, documented)

`DeployRunner.run()` skips any phase marked `completed` in state, without checking whether
the host still matches the plan:

```python
# rodeo/engine/runner.py
if not self.force and is_phase_done(phase, self._plan_name):
    yield PhaseSkipped(phase, "done")
    continue
```

`rodeo plan` detects VM memory/vCPU drift, but `rodeo deploy` / `rodeo up` ignore it unless
the user passes `--force` or `--from`. Tracked as **ROADMAP Phase B2**.

**Risk:** Silent no-op after plan edits — looks successful, nothing changes.

**Remediation:** Extract drift detection from `plan_cmd.py` into `rodeo/drift.py`; wire
`--reconcile` into `DeployRunner` (opt-in first, default later). V1 scope: VM memory/vCPU
only; topology changes deferred.

### 2. Split `~/.rodeo` ownership under `sudo` (real bug)

Secrets resolution correctly uses the invoking user's home via `_invoking_home()` in
`config.py`, but state, logs, kubeconfig, and the success screen use bare `Path.home()`:

| Path | Under `sudo rodeo up` |
|------|------------------------|
| Secrets (load) | `/home/user/.rodeo/secrets.yaml` ✓ |
| State | `/root/.rodeo/state/` ✗ |
| Logs | `/root/.rodeo/logs/` ✗ |
| Kubeconfig | `/root/.rodeo/harvester-kubeconfig` ✗ |
| Success screen passwords | reads `/root/.rodeo/secrets.yaml` ✗ |

**Affected modules:** `state.py`, `secretgen.py`, `success.py`, `runner.py`, `cluster.py`,
`clean.py`, `init_cmd.py`, `generate_cmd.py`, `config.py` (`_LAST_LAB_FILE`).

**Symptom:** After `rodeo up` (self-escalates for deploy), `rodeo status` / `rodeo plan` as
the normal user may show empty phase state; the success screen may not display passwords
even though deploy succeeded.

**Remediation:** Centralize `rodeo_home()` using `_invoking_home()` / `home_of_invoking_user()`
for every path under `~/.rodeo`.

**Status:** Fixed — see `rodeo/paths.py` and fix log below.

### 3. Instruqt download fragility — `get_url` still used in PXE path

`rancher_image.yml` correctly uses `curl -4 --http1.1` (Instruqt-safe), but Harvester PXE
artifacts and the ISO download still use Ansible `get_url`:

- `rodeo/data/ansible/roles/vms/tasks/images.yml` — Harvester ISO
- `rodeo/data/ansible/roles/pxe_server/tasks/files.yml` — vmlinuz, initrd, rootfs

On Instruqt hosts with AAAA records and no IPv6 routing, Python urllib tries IPv6 first →
`errno 101 Network unreachable`. Documented in `CLAUDE.md` but not fixed on all paths.

**Remediation:** Port the `curl -4 --http1.1` shell pattern from `rancher_image.yml` to
`images.yml` and `pxe_server/tasks/files.yml`.

### 4. `plan` diff uses wrong flavors for non-Harvester VMs

```python
# rodeo/commands/plan_cmd.py
def _flavor_of(cfg: dict, vm: str) -> dict:
    flavor = "rancher" if vm == "rancher" else "harvester"
    return cfg.get("resources", {}).get(flavor, {})
```

For `suse-edge`, VMs like `eib`, `edge1`–`edge4` are compared against `harvester` resources
instead of `eib` / `edge-node`. `inventory.py` notes plan should derive flavor from
inventory — wiring never completed.

**Risk:** `rodeo plan` reports false "unchanged" or misses real drift on edge labs.

**Remediation:** Derive flavor per VM from `cfg["vms"]` + inventory `vm_nodes`, or from
`build_inventory()` output.

### 5. `rancher.py` is a 1,910-line monolith

Almost all Rancher/K3s/Elemental/import logic lives in one file. `ROADMAP.md` defers
splitting into `api.py` + `remote.py`. Works today but highest regression risk for Rancher
phase changes.

Two poll loops use raw `time.sleep()` instead of `self._sleep()`, breaking cancellation:

```python
# rodeo/engine/rancher.py (~1359, ~1412)
time.sleep(10)
time.sleep(15)
```

**Remediation:** Split module (later); replace `time.sleep` with `self._sleep` (quick win).

### 6. Network idempotency guard — coarse and unvalidated live

`roles/vms/tasks/network_setup.yml` only checks that *some* `<host mac=` reservation exists,
not that every node in `vm_nodes` has one. Adding a node after first deploy still needs
`--from vms` or `--force`. Documented; **pending live KVM validation** on geekohive.

### 8. Glob-based resource discovery instead of ownership metadata

`clean`, `stop`, `start` discover VMs via substring hints (`harvester`, `rancher`, `edge`,
`eib`, `rodeo`) and glob patterns for disks. Fragile; can miss or over-match.
**ROADMAP Phase B1** (write `rodeo:plan=<name>` into domain XML) is the proper fix.

---

### 9. `ansible-galaxy collection install` on every deploy

`runner.py` runs `ansible-galaxy collection install` on every deploy when
`install_collections=True`. No marker/cache keyed on `requirements.yml` hash. Adds 10–30s
per re-run. Listed in ROADMAP Phase D.

---

### 10. Silent inventory fallback masks definition errors

`profiles/base.py:_load_inventory()` catches all exceptions and returns `None`, falling back
to `static_vms`. A broken `definition.yaml` can deploy the wrong topology with no clear error.

**Remediation:** Fail on `ConfigError` / `FileNotFoundError`; log warning on unexpected
errors; only fall back for missing optional definition in dev.

---

### 11. `??cmd:` resolver uses `shell=True`

`config.py:_resolve_secret_value()` runs `??cmd:` via `subprocess.run(..., shell=True)`.
Fine for advanced/CI; document as advanced-only. Low risk (local plans).
