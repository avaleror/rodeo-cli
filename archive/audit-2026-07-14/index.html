    rodeo-cli code audit — 2026-07-14¶

    Technical audit of /Users/avalero/GitHub/rodeo-cli against CLAUDE.md, ROADMAP.md, CONTEXT.md, and the live codebase. Conducted before a fix pass; issues are ordered by severity with suggested remediation.

    Repo state at audit time: main @ v0.12.0 · ruff clean · 188/190 tests passing locally (Python 3.14; 2 brittle assertion failures from Rich ANSI markup).

    Executive summary¶

    Area Verdict
    Architecture Solid declarative-deployment model; main debt is phase-level vs resource-level idempotency
    Code quality Good modularity in commands/profiles; rancher.py is a maintainability hotspot
    Tests Strong unit suite; 2 brittle failures locally; no automated KVM integration in CI
    Docs CONTEXT.md / CLAUDE.md lag behind main (v0.12.0, ~190 tests)
    Production readiness Bare-metal validated for most profiles; Instruqt queue largely pending

    Critical / high severity¶

    1. Phase-level idempotency hides resource drift (known, documented)¶

    DeployRunner.run() skips any phase marked completed in state, without checking whether the host still matches the plan:

    # rodeo/engine/runner.py
if not self.force and is_phase_done(phase, self._plan_name):
    yield PhaseSkipped(phase, "done")
    continue

    rodeo plan detects VM memory/vCPU drift, but rodeo deploy / rodeo up ignore it unless the user passes --force or --from. Tracked as ROADMAP Phase B2.

    Risk: Silent no-op after plan edits — looks successful, nothing changes.

    Remediation: Extract drift detection from plan_cmd.py into rodeo/drift.py; wire --reconcile into DeployRunner (opt-in first, default later). V1 scope: VM memory/vCPU only; topology changes deferred.

    2. Split ~/.rodeo ownership under sudo (real bug)¶

    Secrets resolution correctly uses the invoking user's home via _invoking_home() in config.py, but state, logs, kubeconfig, and the success screen use bare Path.home():

    Path Under sudo rodeo up
    Secrets (load) /home/user/.rodeo/secrets.yaml ✓
    State /root/.rodeo/state/ ✗
    Logs /root/.rodeo/logs/ ✗
    Kubeconfig /root/.rodeo/harvester-kubeconfig ✗
    Success screen passwords reads /root/.rodeo/secrets.yaml ✗

    Affected modules: state.py, secretgen.py, success.py, runner.py, cluster.py, clean.py, init_cmd.py, generate_cmd.py, config.py (_LAST_LAB_FILE).

    Symptom: After rodeo up (self-escalates for deploy), rodeo status / rodeo plan as the normal user may show empty phase state; the success screen may not display passwords even though deploy succeeded.

    Remediation: Centralize rodeo_home() using _invoking_home() / home_of_invoking_user() for every path under ~/.rodeo.

    Status: Fixed — see rodeo/paths.py and fix log below.

    3. Instruqt download fragility — get_url still used in PXE path¶

    rancher_image.yml correctly uses curl -4 --http1.1 (Instruqt-safe), but Harvester PXE artifacts and the ISO download still use Ansible get_url:

    • rodeo/data/ansible/roles/vms/tasks/images.yml — Harvester ISO
    • rodeo/data/ansible/roles/pxe_server/tasks/files.yml — vmlinuz, initrd, rootfs

    On Instruqt hosts with AAAA records and no IPv6 routing, Python urllib tries IPv6 first → errno 101 Network unreachable. Documented in CLAUDE.md but not fixed on all paths.

    Remediation: Port the curl -4 --http1.1 shell pattern from rancher_image.yml to images.yml and pxe_server/tasks/files.yml.

    4. plan diff uses wrong flavors for non-Harvester VMs¶

    # rodeo/commands/plan_cmd.py
def _flavor_of(cfg: dict, vm: str) -> dict:
    flavor = "rancher" if vm == "rancher" else "harvester"
    return cfg.get("resources", {}).get(flavor, {})

    For suse-edge, VMs like eib, edge1–edge4 are compared against harvester resources instead of eib / edge-node. inventory.py notes plan should derive flavor from inventory — wiring never completed.

    Risk: rodeo plan reports false "unchanged" or misses real drift on edge labs.

    Remediation: Derive flavor per VM from cfg["vms"] + inventory vm_nodes, or from build_inventory() output.

    5. rancher.py is a 1,910-line monolith¶

    Almost all Rancher/K3s/Elemental/import logic lives in one file. ROADMAP.md defers splitting into api.py + remote.py. Works today but highest regression risk for Rancher phase changes.

    Two poll loops use raw time.sleep() instead of self._sleep(), breaking cancellation:

    # rodeo/engine/rancher.py (~1359, ~1412)
time.sleep(10)
time.sleep(15)

    Remediation: Split module (later); replace time.sleep with self._sleep (quick win).

    6. Network idempotency guard — coarse and unvalidated live¶

    roles/vms/tasks/network_setup.yml only checks that some <host mac= reservation exists, not that every node in vm_nodes has one. Adding a node after first deploy still needs --from vms or --force. Documented; pending live KVM validation on geekohive.

    Medium severity¶

    7. time.sleep() outside engine poll loops¶

    File Usage
    start_cmd.py VIP wait loop (10s)
    stop_cmd.py, clean.py, restart.py shutdown polling
    start_if_needed_cmd.py VM start wait
    runner.py firewalld/service waits
    app.py TUI refresh (acceptable)

    cluster.py and most of rancher.py correctly use self._sleep().

    8. Glob-based resource discovery instead of ownership metadata¶

    clean, stop, start discover VMs via substring hints (harvester, rancher, edge, eib, rodeo) and glob patterns for disks. Fragile; can miss or over-match. ROADMAP Phase B1 (write rodeo:plan=<name> into domain XML) is the proper fix.

    9. ansible-galaxy collection install on every deploy¶

    runner.py runs ansible-galaxy collection install on every deploy when install_collections=True. No marker/cache keyed on requirements.yml hash. Adds 10–30s per re-run. Listed in ROADMAP Phase D.

    10. Silent inventory fallback masks definition errors¶

    profiles/base.py:_load_inventory() catches all exceptions and returns None, falling back to static_vms. A broken definition.yaml can deploy the wrong topology with no clear error.

    Remediation: Fail on ConfigError / FileNotFoundError; log warning on unexpected errors; only fall back for missing optional definition in dev.

    11. ??cmd: resolver uses shell=True¶

    config.py:_resolve_secret_value() runs ??cmd: via subprocess.run(..., shell=True). Fine for advanced/CI; document as advanced-only. Low risk (local plans).

    13. Two failing tests (brittle assertions, not logic bugs)¶

    On Python 3.14 locally:

    • tests/test_self_update.py::test_successful_update_reports_fresh_version — Rich ANSI markup splits "0.11.2" across escape sequences
    • tests/test_up_cmd.py::test_up_with_custom_profile_deploys_in_place — same for "custom profile 'mycustom'"

    Remediation: Strip ANSI in assertions or check independent substrings.

    14. Instruqt validation queue entirely pending¶

    Per ROADMAP.md, no bundled profile has been end-to-end validated on an Instruqt builder since recent fixes (DNAT hook, network idempotency guard, harvester_auto_import default). Gate before any workshop track ships.

    What is working well (do not change without cause)¶

    • Event-driven DeployRunner with typed events — clean TUI/plain separation
    • Profile standardization in profiles/base.py — thin data classes, shared phase dispatch
    • Ansible idempotency in PXE network.yml (template for other roles)
    • Secret resolution fail-closed via validate_config()
    • Drift guards in tests/test_ansible_consistency.py
    • clean --refresh opt-in (no version strand on pinned hosts)
    • Live bare-metal validation for rancher, test, harvester-ha, harvester-2n
